## 1. Product Scope & Default Zero-Telemetry Statement

Cosmos MCP provides a controlled local workspace connection service for **Web Google Gemini (Task Mode, including the same-account Gemini mobile app)** and **Web ChatGPT (first-time auto-setup via the `Work` mode managed browser or manual local plugin installation; once installed, supports regular `Chat` mode for daily development and `Work` mode for long-running/scheduled tasks; full-featured `/mcp` for Workspace plans and read-only `/mcp/readonly` for personal plans)**.

By default, the software does not collect, aggregate, or upload usage telemetry, device fingerprints, hostnames, directory paths, tool invocation logs, or workspace file contents to the maintainers or any third-party analytics service, and honors the `DO_NOT_TRACK=1` environment variable.

## 2. Optional Multi-Gateway Coexistence & Data Flow by Channel

The project maintainers do not operate a centralized relay server that retains user traffic. The console provides 3 categories of remote HTTPS encrypted gateways that can be toggled independently and run side by side, or disabled altogether for local loopback self-checks:

1. **Option 1: Built-in OpenSSH Direct Connect & Cloudflare Temporary Encrypted Tunnel Backup (enabled by default on first launch, `--mode openssh` / `--mode public_gateway` and `--mode cloudflare` / `--mode trycloudflare`)**:
   - **Primary Channel (`--mode openssh`)**: Invokes your OS built-in OpenSSH (`ssh`) client with a locally generated persistent `Ed25519` asymmetric keypair (`<state_dir>/secrets/srvus_ed25519`; the private key stays strictly on local disk under current-user ACLs and is never uploaded) to establish an `SSHv2` encrypted reverse tunnel (`chacha20-poly1305@openssh.com` / `aes256-gcm@openssh.com` authenticated encryption and `curve25519-sha256` key exchange, with `User=nomatch` and `IdentitiesOnly=yes` isolating your OS username and other SSH keys) to the public relay `srv.us:22`, obtaining a fixed `https://xxxxx.srv.us` HTTPS URL that remains unchanged across reboots.
   - **Backup Channel `Cloudflare Temporary Encrypted Tunnel (trycloudflare Backup)` (`--mode cloudflare` / `--mode trycloudflare`)**: If outbound port `22` is blocked on the current network (or when the independent backup toggle is enabled side by side), the daemon launches the official `cloudflared` client (first-time auto-download enforces mandatory **`SHA-256`** checksum verification) to establish an outbound port `443` **`TLS + HTTP/2`** (`--protocol http2`) encrypted tunnel providing a temporary `https://*.trycloudflare.com` URL.
   - **Encryption Chain & Edge Termination Boundary**: Traffic from Web Google Gemini and Web ChatGPT uses standard `HTTPS/TLS` over the public internet; public TLS terminates at the `srv.us` (or Cloudflare) public edge relay and forwards back to your PC (`127.0.0.1`) over the encrypted OpenSSH `SSHv2` reverse tunnel (or `cloudflared` outbound `TLS + HTTP/2` tunnel; not end-to-end zero-knowledge blind TLS passthrough), where the local loopback ingress shim (`_LocalTunnelIngressShim`) and `GatewayContextASGI` loopback checks (detecting `Cf-Ray` / `X-Forwarded-*` headers) hard-block `/studio`, `/api/studio`, and `/oauth/local-bridge` with HTTP `403`, followed by `/u/<endpoint_secret>/mcp` stealth-path filtering and local `OAuth 2.1 + PKCE S256` (SHA-256) and [RFC 8707](https://datatracker.ietf.org/doc/html/rfc8707) resource-audience isolation (tokens stored only as `SHA-256` digests; to terminate public TLS directly on your own server, use Option 3 self-hosted Linux VPS). Optional Identity Recovery Card PNGs are encrypted locally with `scrypt` (`N=16384, r=8, p=1`) + `AES-256-GCM`.
2. **Option 2: `Cloudflare Dedicated Fixed Gateway` (`--mode workers_dev` / `cf_workers`)**:
   - **Deployment & Immediate API Token Shredding**: Uses a least-privilege Cloudflare API token provided once by the user to deploy a free `Worker + SQLite Hibernation Durable Object` relay gateway under the user's own Cloudflare account (e.g., `https://your-worker.your-subdomain.workers.dev` or a custom domain on the same account). Immediately upon deployment completion, `shred_cloudflare_api_token` zero-overwrites, fsyncs, truncates, and destroys the API token from memory and temporary cache, leaving zero plaintext API token on disk, and supports exporting `scrypt` (`N=16384, r=8, p=1`) + `AES-256-GCM` encrypted PNG recovery cards.
   - **Encryption Chain & Edge Termination Boundary**: Daily runtime uses pure Python stdlib `ssl.create_default_context()` certificate-chain verification to establish an outbound **`443 WSS` (`TLS 1.2 / TLS 1.3` encrypted WebSocket)** binary multiplexed persistent connection (zero external binary dependencies). A local **`256-bit` (64-hex) `workers_tunnel_secret`** is generated under Windows `icacls` / Unix `0600` current-user-only ACLs, and the Worker's `/_cosmos_tunnel` endpoint verifies the `Bearer` tunnel secret in constant time (`constantTimeEqual`) to prevent forged attachments. Public `HTTPS/TLS` terminates at **your own Cloudflare account edge** (where the Worker entry allowlist permits only OAuth and `/mcp*` routes and blocks admin paths), and after forwarding over `443 WSS`, your local server blocks `/studio` admin routes and enforces `OAuth 2.1 + PKCE (SHA-256)` and [RFC 8707](https://datatracker.ietf.org/doc/html/rfc8707) audience isolation.
3. **Option 3: Self-Hosted `24h` Cloud Server Hub or Self-Owned Fixed Domain (`self_hosted`: `--mode vps_hub`, `vps`, `cloudflare_token`, `custom` / `reverse_proxy`)**:
   - **Sub-option A `Self-Hosted 24h Cloud Server Hub` (`--mode vps_hub`) & `Self-Hosted SSH Reverse Tunnel` (`--mode vps`)**: One-click deploys **Caddy v2.11+** on **your own Linux cloud server**, automatically issuing and renewing **`TLS 1.2 / TLS 1.3` ACME certificates** (Let's Encrypt certificate when a domain is bound, or short-lived public-IP ACME certificate + `sslip.io` fallback certificate when no domain is entered), **terminating public TLS 100% on your own server with zero third-party cloud decryption**. Deployment prefers a dedicated locally generated **`Ed25519`** SSH keypair (`<state_dir>/secrets/vps_id_ed25519`, `0600` / current-user ACL), while any SSH password entered during first-time setup is **used in memory for that single handshake only and never saved to disk**. Under `vps_hub`, your PC attaches to `/_cosmos_node` over CA-verified outbound **`443 WSS` (`TLS 1.2/1.3`)** authenticated via `hmac.compare_digest` using a **`256-bit` (64-hex) `vps_node_secret`**, Caddy blocks external access to `/studio` and non-WebSocket `/_cosmos_node`, and the synced remote `auth.json` strips `local_api_token` under `0600` permissions; under `vps`, built-in OpenSSH establishes an **`SSHv2`** (`ChaCha20-Poly1305` / `AES-256-GCM`) `-R` encrypted reverse tunnel; **`OAuth 2.1 + PKCE (SHA-256)`** and [RFC 8707](https://datatracker.ietf.org/doc/html/rfc8707) audience isolation are enforced throughout.
   - **Sub-option B `Cloudflare Named Tunnel` (`--mode cloudflare_token`) & `Generic Self-Hosted HTTPS Reverse Proxy` (`--mode custom` / `reverse_proxy`)**: `cloudflare_token` uses the **`SHA-256`** verified `cloudflared` client to open an outbound port `443` **`TLS + HTTP/2`** (`--protocol http2`) encrypted tunnel, storing the token under user-only ACLs in `secrets/tunnel_token.txt` and redacting logs as `[REDACTED_TUNNEL_TOKEN]`, with public `HTTPS/TLS` terminating at your own Cloudflare Zero Trust edge before reaching localhost; `custom` / `reverse_proxy` terminates public **`HTTPS / TLS 1.2/1.3`** at your self-controlled Caddy / Nginx reverse proxy (or passes through FRP TLS SNI), while local `GatewayContextASGI` checks the trusted `Host` allowlist (returning HTTP `421` for unknown hosts); both block `/studio` locally and enforce `OAuth 2.1 + PKCE (SHA-256)` and [RFC 8707](https://datatracker.ietf.org/doc/html/rfc8707) audience isolation.
4. **Local Loopback Isolated Self-Check Mode (all public gateway toggles off, or `--mode local`)**:
   - When all 3 public gateway toggles are switched off or `--mode local` is explicitly passed, the server listens exclusively on `127.0.0.1` for local console inspection and automated self-checks. Aside from initial runtime setup and explicit user-triggered `pc_web_research` or `pc_browser_use` calls to public web pages, the server initiates no outbound tunnel connections.
5. **Passphrase Hashing & Zero-Plaintext Token Retention Boundary**:
   - The local admin and authorization passphrase is stored as a `hashlib.scrypt` hash with a random 16-byte salt in `<state_dir>/secrets/auth.json` (permissions `0600`) and verified locally only.
   - Web Google Gemini and Web ChatGPT receive only OAuth 2.1 tokens bound to the active gateway audience (personal ChatGPT bindings to `/mcp/readonly` are physically locked to the `server:read` read-only audience) and never see the local plaintext passphrase. Local `state/oauth.sqlite3` stores only SHA-256 hash digests of access and refresh tokens as primary keys, with zero plaintext OAuth tokens written to disk.

## 3. Locally Stored Files & Complete Removal

To allow the user to inspect audit logs, undo file edits, and restore accidentally deleted files, the program stores the following local data solely inside the local state directory (`%LOCALAPPDATA%\CosmosMCP` by default on Windows, `~/.cosmos-mcp` on macOS and Linux):

- `logs/audit.jsonl`: Records local tool call timestamps, tool names, durations, and execution statuses.
- `logs/server.log` and `logs/supervisor.log`: Local server and background supervisor logs, automatically rotated by file size.
- `history/` and `.undo_history/`: Pre-edit file snapshots and files moved to the recoverable trash bin.
- `secrets/auth.json`, `secrets/master_seed`, `secrets/srvus_ed25519`, `secrets/vps_id_ed25519`, `secrets/workers_tunnel_secret.txt`, `secrets/vps_node_secret.txt`, `secrets/tunnel_token.txt`, and `state/oauth.sqlite3`: Stores the passphrase hash, local deterministic seed, persistent OpenSSH / VPS keypairs (current-user-only ACLs), `256-bit` Workers gateway and VPS child-node handshake secrets, Named Tunnel token (redacted in diagnostic logs as `[REDACTED_TUNNEL_TOKEN]`), and SHA-256 hashed OAuth token records (no plaintext OAuth access tokens, Cloudflare deployment API tokens, or VPS SSH passwords are stored).

When exporting diagnostics, `cosmos-mcp doctor --bundle` automatically redacts passphrases, tokens, tunnel subdomains, email addresses, and OS home-directory usernames. To stop background processes and purge all local records in the state directory, run:

```bash
cosmos-mcp uninstall --purge --json
```
