# 04. 三大连接通道选型与网络排障手册

网页版 Google Gemini 与网页版 ChatGPT 运行在云端机房，必须通过具备有效 TLS 证书的标准 HTTPS `443` 地址访问本机服务。本手册对比 Cosmos MCP（`v1.2.1`）内置的 3 类连接通道，提供 Cloudflare 免费 SQLite Durable Object 固定网关与自有云服务器 `24` 小时主站的分步配置流程，并汇总 Windows 代理环境变量、端口受限、Cloudflare 防火墙质询及休眠唤醒重连的排障清单。

## 二、方式 2 实操：部署 Cloudflare 免费 SQLite Durable Object 固定网关

方式 2 全程通过纯 Python 标准库调用 Cloudflare REST 接口完成部署，本机无需安装 Node.js 或 `wrangler` 命令行工具。

### 第 1 步：使用预填模板创建最小权限 API 令牌

1. 打开本地控制台 `http://127.0.0.1:8096`，在「总览与网页连接」页点击展开 **方式 2：登录 Cloudflare 注册一下就行**。
2. 点击卡片上的「打开预填权限的 Cloudflare 令牌创建页」按钮，登录你的 Cloudflare 账号（首次使用可直接用 Google 账号注册并登录）。
3. 页面已自动预填 `Cosmos-MCP-Gateway` 所需的 `4` 项最小权限，无需使用全局 Global API Key：
   - `Account -> Workers Scripts: Edit`（上传并更新中继 Worker 与 Durable Object 脚本）
   - `Account -> Account Settings: Read`（读取账号标识与 `workers.dev` 子域状态）
   - `Zone -> Zone: Read` 与 `Zone -> Workers Routes: Edit`（仅在填写同账号下自定义域名时用于自动查询域名区域并绑定路由）
4. 点击页面底部的 `Continue to summary -> Create Token`，复制生成的 API 令牌字符串。

### 第 2 步：3 秒自动部署与令牌即刻清零销毁

1. 回到本地控制台方式 2 卡片，将复制的 API 令牌粘贴至令牌输入框（若暂不绑定自有域名，自定义域名栏留空即可），点击一键部署按钮。
2. 后台在约 `3` 秒内依次自动执行四步操作：
   - 查询令牌关联的 Cloudflare Account ID；
   - 检查账号下是否已开通 `*.workers.dev` 子域，未开通时自动完成子域认领；
   - 按本机确定性节点前缀生成脚本名 `cosmos-mcp-<节点标识>`，上传内嵌的 `CosmosRelayDO` 模块（采用 SQLite Hibernation Durable Object 与 `17` 字节二进制多路复用帧协议，支持 `32 MiB` 流式请求分片与 `9` 秒切网断线重放缓冲）；
   - 开启子域路由并由本机通过出站 `443 WSS` 建立持久连接。
3. **API 令牌用后即焚与独立开关启停**：网关部署成功并写入固定连接地址后，系统立即调用 `shred_cloudflare_api_token` 对本地缓存令牌执行全零字节覆写、磁盘刷写（`fsync`）与零长度截断移除，本机磁盘不保留任何 Cloudflare API 令牌明文；后续可直接拨动卡片右上角独立开关启停该通道（无需重填令牌），且可与方式 1 或方式 3 同时开启并存。
4. **备份身份恢复卡（可选）**：部署完成后可在控制台点击导出加密 PNG 身份恢复卡，重装系统或迁移电脑时导入该 PNG 图片并输入本机口令即可恢复原网关连接身份。

### 第 3 步：中国大陆 `*.workers.dev` 常驻代理要求与自定义域名免代理方案

在中国大陆运营商 DNS 与公共 DNS 环境下，默认的 `*.workers.dev` 域名存在全量 DNS 污染，本机无代理裸连会 `100%` 握手超时。请按以下两种方案之一运行：

- **方案 A（未绑定自定义域名，继续使用默认 `*.workers.dev`）**：
  1. **后台运行期间保持代理常开**：本机必须保持系统 HTTP/HTTPS 代理（如 Clash、Mihomo、v2rayN，或环境变量 `HTTPS_PROXY` / `WSS_PROXY`）处于开启状态，且分流规则允许代理访问 `*.workers.dev`，以维持本机后台到 Cloudflare 边缘的 `443 WSS` 长连接隧道。
  2. **首次浏览器 `/consent` 授权同样走代理**：首次在网页端点击连接并跳转 `/consent` 授权页时，本机浏览器也需通过代理访问 `*.workers.dev`（若规则分流漏掉 `*.workers.dev` 可临时切换全局代理完成首次授权，但切回规则模式后日常后台运行仍须保证规则将 `*.workers.dev` 纳入代理，关闭代理或将 `*.workers.dev` 设为直连会导致后台隧道断连）；若配置了 `NO_PROXY`，必须保留 `127.0.0.1,localhost,::1`。
- **方案 B（国内免代理直连方案：绑定同账号 Active Zone 自定义域名）**：
  1. 将你拥有的域名（或已接入 Cloudflare 的免费二级域名）添加至同一个 Cloudflare 账号下托管并处于激活状态（Active Zone）。
  2. 在方式 2 部署时一并在「自定义域名」输入框填入子域名（例如 `mcp.example.com`，无需提前手动新建 A 记录或 CNAME 记录），点击部署后系统会自动通过 `Workers Domains` 接口绑定该域名并签发边缘 HTTPS 证书，直接走未受 `workers.dev` 污染的边缘节点实现国内免代理直连（也可改用方式 1 默认 `*.srv.us` 或方式 3 自有云服务器）。
  3. 若此前已完成 `*.workers.dev` 部署且 API 令牌已销毁，可在 Cloudflare 后台进入 `Workers & Pages -> cosmos-mcp-<节点标识> -> Settings -> Domains & Routes` 手动添加 `Custom Domain`，回到本地控制台填入该域名保存即可（双域名同时纳入受信任主机列表；自定义域名请按第四章第 3 节关闭 `Bot Fight Mode`）。

## 三、方式 3 实操：一键部署云服务器 24 小时主站与多设备组网

### 1. 一键 SSH 部署云端 24 小时主站

1. **检查服务器前置条件**：准备一台 Debian / Ubuntu 等主流 Linux 云服务器，在云厂商控制台安全组放行入站 TCP `80` 与 `443` 端口（海外与港澳台服务器无需域名即可自动签发公网 IP 证书；中国内地机房受接入商合规网关限制，需一并填写已完成 ICP 备案并解析到该 IP 的自有域名）。
2. **填写参数一键建站（支持 SSH 密码或密钥免密）**：在本地控制台展开 **方式 3：自己的服务器和域名**，填入云服务器公网 IP、SSH 端口（默认 `22`）与登录用户名（如 `root` 或具 `sudo` 权限账号），可填写 SSH 密码（仅当次内存使用不落盘），也可填写本地 SSH 私钥路径（如 `~/.ssh/id_ed25519`）或勾选「使用本机默认 SSH 密钥免密登录」免填密码；有域名则在域名栏填入 `mcp.example.com`，点击一键部署。
3. **后台自动初始化**：本地通过无窗口 `SSH_ASKPASS` 免明文回显模式连接服务器，自动检测物理内存（小于 `256MB` 的轻量主机自动创建交换文件防止内存不足），校验 `80`/`443` 端口连通性，自动部署 HTTPS 反向代理及证书（证书目录持久化保存以避免触发签发机构的周频率上限），启动云端 `24` 小时 Cosmos MCP 主站，并将当前个人电脑经出站 `443 WSS` 挂载为主站下的远程子节点。

### 2. 绑定 Cloudflare Named Tunnel 或自有反代域名

若你已有托管在 Cloudflare Zero Trust 的固定隧道令牌（`--tunnel-token`），或已在路由器/服务器上自行搭建好反向代理，可在方式 3 切换至固定域名子项直接保存，或使用命令行启动并注册开机自启。启用 `Cloudflare Named Tunnel`（`--mode cloudflare_token`）前请确认以下前置条件：

- **本机 `cloudflared` 二进制依赖**：若系统 `PATH` 未预装 `cloudflared`（且未设置 `COSMOS_CLOUDFLARED_BIN`），首次启用时程序会自动从 [GitHub Releases](https://github.com/cloudflare/cloudflared/releases/latest) 或 `COSMOS_CLOUDFLARED_MIRROR` HTTPS 镜像下载二进制至状态目录 `bin/`；国内无代理环境下载缓慢时可开启系统代理、配置 `COSMOS_CLOUDFLARED_MIRROR` 或预先安装 `cloudflared`。
- **Zero Trust 路由与防火墙放行**：需具备 Cloudflare Zero Trust 账号与已激活托管域名（Active Zone），在 Zero Trust 后台 `Networks -> Tunnels -> Public Hostname` 将目标域名转发至 `http://127.0.0.1:8096`，并按第四章第 3 节关闭 `Bot Fight Mode`、对 `/mcp*` 与 OAuth 路径跳过托管质询。

```bash
# 使用 Cloudflare Named Tunnel 令牌绑定固定域名并开启登录自启
cosmos-mcp start --mode cloudflare_token --tunnel-token <粘贴你的TOKEN> --public-url https://mcp.example.com --autostart

# 使用已有 VPS SSH 反向端口映射连接自有反代域名
cosmos-mcp start --mode vps --vps-ssh ubuntu@203.0.113.10 --vps-remote-port 18096 --public-url https://mcp.example.com --autostart
```

### 3. 多设备组网：tool_prefix 独立前缀区分与 target="auto" 路由

同时管理多台电脑与服务器时，可按连接架构选择以下两种方式：

1. **多连接器独立 `tool_prefix` 区分（适用于多台电脑各自采用方式 1 或方式 2 独立上线）**：
   - 单台电脑保持默认 `pc` 即可；多设备同时上线时，在主力台式机的控制台「工具中心与安全开关」页将工具前缀保存为 `desk`（或启动加 `--tool-prefix desk`），在笔记本电脑上将工具前缀保存为 `laptop`（或启动加 `--tool-prefix laptop`；注：`--prefix` 参数用于同一台电脑运行多实例时的配置槽位隔离）。
   - 在网页版 Gemini 或网页版 ChatGPT 中分别添加 `Cosmos-Desk` 与 `Cosmos-Laptop` 两个连接器。
   - 在同一聊天窗口内可直接按前缀分工调用，例如让 `desk_run_python` 在台式机跑数据处理，同时让 `laptop_edit_file` 更新笔记本上的汇报文档。控制台热修改前缀后，当前对话已加载的旧前缀名称仍自动兼容路由。
2. **单入口 `target="auto"` 自动路由（适用于方式 3 云端 24 小时主站挂接本地电脑）**：
   - 网页端只需绑定云端主站的 `https://<主站域名>/mcp` **一个连接器**，工具列表始终保持精简的 `16` 项核心工具，不会因接入多台设备导致工具 Schema 成倍膨胀。
   - 全部 `16` 项工具均内置可选路由参数 `target="auto"`：当传入 `/srv/api` 或 `~/projects/demo` 等服务器工作区路径时直接在云端主站本地执行；当传入 `D:\Work\my-project` 等个人电脑开放目录路径时，主站在路径预检前自动通过 WSS 多路复用通道转发至对应电脑执行（也可显式传 `target="server"`、`target="local"` 或节点别名定向调用）。
   - 当个人电脑关机或外出断网时，云端主站保持 `24` 小时在线响应服务器任务，针对离线电脑的调用秒级返回 `ERR_NODE_OFFLINE`，不中断网页端整个 MCP 会话。

## 四、真实网络与连接排障清单

### 1. 中国大陆 `*.workers.dev` 常驻代理、环境变量 `NO_PROXY` 与 `cloudflared` 下载镜像配合

本机开启 Clash、Mihomo 或 v2rayN 等代理软件（常见本地 HTTP 代理端口如 `127.0.0.1:7897`）或在国内网络使用 Cloudflare 相关通道时，请核对以下三项配置：

- **默认 `*.workers.dev` 常驻代理要求与存活探测**：`*.workers.dev` 在国内存在全量 DNS 污染（裸连 `100%` 超时），未绑定自定义域名时必须保持本地 HTTP/HTTPS 代理常开且分流规则覆盖 `*.workers.dev`。出站 `443 WSS` 客户端按 `WSS_PROXY` -> `HTTPS_PROXY` -> `ALL_PROXY` -> 操作系统代理设置顺序自动读取代理，每 `1.0` 秒轮询代理变化并在切换后 `2` 秒内重连。若退出代理软件后系统代理或环境变量仍残留指向未监听的 `127.0.0.1:7897`，控制台与 Windows 托盘会提示 **「检测到本机代理端口未响应，请确认 Clash 等代理软件是否已退出」**；此时重启代理软件（继续使用 `*.workers.dev` 时）或改绑同账号自定义域名 / 切换 `*.srv.us` 后关闭残留系统代理即可恢复。
- **`NO_PROXY` 环境变量正反边界**：
  1. **必须保留回环地址**：若配置了 `NO_PROXY`（或 `no_proxy`），务必包含 `127.0.0.1,localhost,::1`。若缺失回环地址，浏览器访问 `http://127.0.0.1:8096` 控制台或 `/consent` 授权页发起的 `800ms` 本机回环免密请求会被送入外部代理，导致同机身份校验失败而退回手动输口令。
  2. **勿将公网网关域名写入 `NO_PROXY`**：在国内借助本地代理连接 Cloudflare 时，请确认 `NO_PROXY` 中没有误填 `*`、`*.workers.dev` 或 `*.trycloudflare.com`，避免后台隧道被强制绕过代理直连污染 IP 超时。
- **`cloudflared` 首次下载与 `COSMOS_CLOUDFLARED_MIRROR` 镜像**：方式 1 回退通道（`*.trycloudflare.com`）与方式 3 子项（`--mode cloudflare_token`）均需调用官方 `cloudflared` 客户端（方式 2 `workers_dev` 纯 Python 实现，无需 `cloudflared`）。若系统 `PATH` 未安装，程序首次启用时自动从 [GitHub Releases](https://github.com/cloudflare/cloudflared/releases/latest) 校验 SHA-256 下载至状态目录 `bin/`；国内无代理环境若拉取 GitHub 缓慢，可开启系统代理、设置环境变量 `COSMOS_CLOUDFLARED_MIRROR` 指向可信 HTTPS 镜像前缀，或预先安装 `cloudflared`（也可设 `COSMOS_CLOUDFLARED_BIN` 指定本地二进制路径）。

### 2. 出站 22 端口受限自动切换 HTTPS 443 通道与 Quick Tunnel 边界

- **现象**：在高校校园网、企业办公内网或公共热点下，方式 1 默认的 `*.srv.us` 免登录固定网址显示连接超时，或回退 `*.trycloudflare.com` 后偶发报 HTTP `530` / `1033`。
- **原因与处理**：`*.srv.us` 基于系统 OpenSSH 反向隧道（出站 TCP `22` 端口），常被内网出口防火墙拦截。本地守护进程检测到 `22` 端口握手失败后，会在 `4` 秒内自动切换至走 `443` 端口的 `*.trycloudflare.com` 快速通道。注意 [Cloudflare Quick Tunnels](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/) 免注册但每次重启必换域名、无在线率 SLA、强制单控制流（`ha-connections:1`）重连存在 `4–21` 秒空窗（期间返回 HTTP `530`/`1033`）且限 `200` 并发在途请求；跨境高丢包环境下建议开启系统 HTTP 代理降低断流率，长期使用建议切换为 **方式 2**（纯出站 `443 WSS` 固定网址）或 **方式 3**（自有云服务器 `24h` 主站 / `Cloudflare Named Tunnel`）。

### 3. Cloudflare WAF / Bot Fight Mode 拦截 OAuth 回调

- **现象**：使用托管在 Cloudflare 的自定义域名（方式 2 自定义域或方式 3）时，本机浏览器打开 `https://mcp.example.com/healthz` 返回正常 JSON，但在网页版 Gemini 或网页版 ChatGPT 点击连接器绑定时报「无法获取 OAuth 元数据」、动态注册 `/register` 失败或返回 HTTP `403`。
- **原因**：网页端 AI 绑定与调用工具时，由 Google 与 OpenAI 云端后端服务器直接请求 `/.well-known/oauth-protected-resource*`、`/.well-known/oauth-authorization-server*`、`/register`、`/token` 及 `/mcp*`。若该域名开启了 Cloudflare **Bot Fight Mode（机器人对抗模式）** 或配置了全局 **Managed Challenge / JS Challenge** 规则，云端机房请求无法执行浏览器前端脚本质询而被拦截。
- **处理步骤**：
  1. 登录 Cloudflare 控制台选中该域名，进入 `Security -> Bots`，关闭 **Bot Fight Mode**（若使用 Pro 及以上计划的 Super Bot Fight Mode，将自动化流量策略对子域放行）。
  2. 进入 `Security -> WAF -> Custom rules`，新建一条匹配条件为 `Hostname equals mcp.example.com`（或 URI 路径匹配 `/.well-known/*`、`/register`、`/authorize`、`/token`、`/mcp*`）的规则，动作设为 `Skip` 并勾选跳过所有剩余自定义规则、托管质询与速率限制。
  3. 请勿配置仅允许 Google IP 段或仅允许 OpenAI IP 段的来源白名单，以免同时使用网页版 Gemini 与网页版 ChatGPT 时阻断另一方连接器请求。

### 4. 休眠唤醒与切换热点后的重连验证

- **后台重连机制**：Windows 笔记本在插交流电源且开启控制台「插电防自动休眠」开关时保持常驻唤醒；拔掉电源改用电池供电时自动解除防休眠保护续航。当合盖睡眠后重新开盖唤醒（系统单调时钟与挂钟差值跳变 `>3.0` 秒），或在 Wi-Fi 与手机热点之间切换（零流量 UDP 探测到出口源 IP 变化）时，`NetworkChangeDetector` 会在约 `1.5` 秒内主动重建网关长连接，Cloudflare SQLite Durable Object 网关同步为在途请求提供 `9` 秒挂起等待窗口。
- **验证步骤**：
  1. 电脑唤醒后等待 `2` 秒，查看 Windows 任务栏右下角托盘圆点是否由橙色（重连中）变回绿色或蓝色，或打开 `http://127.0.0.1:8096` 查看右上角连接状态徽标。
  2. 若连续重连失败，托盘圆点切换为红色并在鼠标悬停提示及控制台顶部状态横幅中指明断网或本地代理未启动原因（全程静默自动重连，不弹系统气泡抢占焦点），按提示恢复网络或代理即可。
  3. 回到网页版 Gemini 或 ChatGPT 原对话窗口直接发送 `@Cosmos 调用 pc_get_status 确认连接已恢复`，正常返回本机状态即表示通道恢复完毕。
