# 05. 多智能体并行子任务与实战工作流教程

本教程面向已将本地 Cosmos MCP（`v1.2.1`）连通 **网页版 Google Gemini（任务模式，含同账号手机端 Gemini App）** 或 **网页版 ChatGPT（已安装 `WebAI2PC` 插件：日常改代码跑脚本用 `Chat` 模式省额度，跨应用长程与定时任务用 `Work` 模式）** 的用户，分步说明宿主操作守则配置、多路并行子任务（`invoke_subagent`）分工、PDF / 图片多模态读取与 Word / Excel 原位修订、长耗时编译自动转后台轮询，以及按需热开启受管浏览器（`browser`）与桌面窗口自动化（`cua`）扩展包的实操方法与运行边界。

## 一、导入 AI 操作守则与首句唤醒实践

### 1. 将「复制 AI 操作守则」存入宿主 Skills 或 Instructions

本地控制台内置了与当前工具前缀及 `16` 项核心工具契约对齐的操作守则模板（对应仓库 `host_skills/SKILL.md`），提前存入宿主后可省去在每次对话重复交代安全边界与工具参数格式：

1. 打开本地 `Cosmos Studio` 控制台（`http://127.0.0.1:8096`），展开「首次绑定步骤与唤醒词」点击 **「复制 AI 守则」** 或 **「复制 ChatGPT 守则」**。
2. **网页版 Google Gemini**：
   - 在左侧栏点击 `Customize（自定义） -> Skills（技能）`，新建一条自定义技能并粘贴保存。
   - 同时检查 `https://gemini.google.com/customize/connectors`（或左下角菜单 `Personal Intelligence -> Connected Apps`）中对应连接器的详情页，确保顶部的 `App actions` 总开关已设为 `Always allow（始终允许）`。注意不要在聊天对话流弹出的单张工具确认卡片上单独点击允许，单卡授权会按单个工具覆盖设置，导致同连接器下的其余工具退回逐次弹窗确认。
3. **网页版 ChatGPT（区分 `Skills` 与 `Instructions` 存放及 `Chat` / `Work` 调用）**：
   - **守则存放**：在工作区、桌面端或插件包环境可存入原生 `Skills`；网页版 `Chat` 模式与 `Work` 模式均可将守则粘贴到常用 `Project（项目）Instructions` 或自定义指令框中复用。
   - **按场景调用 `@WebAI2PC`**：日常查改本地代码、原样修订 Word / Excel 与跑测试优先在 **`Chat` 模式**输入 `@WebAI2PC`（响应快，走普通对话限额，零扣减 `Work / Codex` 智能体额度）；需要结合受控浏览器、跨邮件/Slack/网盘生成多步交付物或设置 `Scheduled Tasks` 定时任务时，在 **`Work` 模式**输入 `@WebAI2PC`。

### 2. 首句携带连接器名称与外部搜索隔离

- **网页版 Gemini 首句唤醒**：每次新建任务模式对话时，在首句输入 `@你在连接器里填写的名称`（例如 `@WebAI2PC` 或 `@Cosmos`）并点选输入框弹出的连接器标签（也可点击控制台横幅的「一键复制首句唤醒测试词」或 Windows 托盘右键菜单「复制首句唤醒词」），例如：
  ```text
  @WebAI2PC 先用 pc_get_status 查看当前开放的工作目录与工作区技能，再梳理 D:\Work\my-project 的模块结构。
  ```
  当同一对话轮次较多触发上下文自动压缩，或某轮简短追问未显式带 `@连接器名称` 导致工具未展开时，操作守则会自动引导模型先重新展开所需的 `pc_*` 工具再继续执行。
- **公开网页与 GitHub 检索走本机工具**：在已挂载本连接器的主会话中查阅外部文档、报错讨论或开源实现时，直接让 AI 调用本机只读工具 `pc_web_research(action="search"|"github_search"|"fetch")`，避免在同一主对话混调宿主内置联网搜索导致连接器免审批状态降级。

## 二、网页版 Gemini 任务模式按目录拆分并行子任务（invoke_subagent）

处理中大型代码库或多份文档对比时，如果在一个对话窗口内连续顺序读取二三十个文件，原始文件内容会迅速占满主会话上下文窗口并拖慢响应速度。网页版 Gemini 任务模式支持通过 `invoke_subagent` 派生异步子任务并行处理。

### 1. 适合拆分并行子任务的典型场景

- **跨目录代码审查与检索**：按 `backend/`、`frontend/`、`tests/` 等子目录拆成多路子任务同时排查接口契约、异常捕获或性能瓶颈。
- **多模块独立验证与批量探针**：各子任务在各自模块目录内运行只读 `pc_batch_probe` 聚合统计（预置 `PROJ`、`rg`、`outline`、`list_dir` 与 `RESULT`），仅将汇总表与精确文件路径行号返回主对话。
- **多份长文档或 PDF 独立摘录**：每路子任务负责读取并核对 `1` 至 `2` 份大型 PDF 或设计文档，主对话负责交叉比对结论。

### 2. 派发规范与防并发写冲突边界

1. **单批路数与连接器传递**：单批并行子任务控制在 `2` 至 `4` 路（不超过平台单批 `5` 路并发上限，子任务内不再嵌套派生子任务）。每路子任务的任务说明开头携带 `@你在连接器里填写的名称`（如 `@WebAI2PC` 或 `@Cosmos`）并指定独立的 `caller` 标签（如 `caller="sub-api-check"`、`caller="sub-db-check"`），便于在控制台审计流水中区分来源。
2. **避免多子任务同时写同一文件**：虽然 `pc_edit_file` 与 `pc_write_file` 支持 `expected_sha256` 乐观锁校验，多路子任务同时修改同一个文件仍会造成哈希失配回退。实战中遵循两条分工边界：
   - **多路只读检索 + 主会话统一修改（默认推荐）**：所有并行子任务仅调用 `pc_find_files`、`pc_search_code`、`pc_code_intel`、`pc_read_file` 或 `pc_batch_probe` 定位问题行号与修改草案；待全部子任务完成后，由主对话统一按序调用 `pc_edit_file` 修改并执行测试。
   - **严格按互不重叠的独占文件分片写入**：若需要多路子任务并行生成独立单测文件或分章节文档，在派发提示词中为每路子任务列出独占写入文件路径清单，禁止跨清单触碰其他文件。

可直接复用的并行任务唤醒提示词示例：

```text
@Cosmos 请将排查工作拆分为 3 个并行子任务，分别对 D:\Work\my-project 下的 src/auth、src/orders、src/payments 三个目录执行只读审查（使用 pc_code_intel 与 pc_read_file 定位未处理异常和缺失的边界测试，子任务内不要修改任何文件）。等 3 路子任务全部返回行号与修复方案后，在主对话统一用 pc_edit_file 完成修复并运行测试。
```

## 三、Office 文档与多模态实操（PDF、图片、Word、Excel 与一键回滚）

Cosmos MCP 内置纯 Python 与标准库文档处理管线，无需在本机安装额外 C 编译扩展或手动向网页上传附件即可直接读写本地办公文档与图片。

### 1. 直接读取本地图片与 PDF 文档

- **本地图片原生多模态查看**：调用 `pc_read_file(path="D:\\Work\\my-project\\docs\\architecture.png")` 读取本地 `.png`、`.jpg`、`.jpeg`、`.webp` 图片时，服务端对网页版与手机端 Gemini 直接返回原生 `EmbeddedResource` 图像数据（小于等于 `160 KiB` 的 PNG 无损直通，超尺寸大图自动等比缩放，同时提供 `30` 分钟有效期的 HMAC 签名只读预览路由），AI 可直接对照本地界面截图排查布局错位或识别图表数字。
- **PDF 与多格式文档提取**：`pc_read_file` 支持直接提取 `.pdf`、`.docx`、`.xlsx`、`.pptx`、`.ipynb` 文本内容；读取中文 PDF 时自动执行 `/CIDFont`、`/Identity-H`、`/ToUnicode` 字体映射与控制符结构检查，防止遇到未嵌入字形编码的扫描或特殊字体 PDF 时返回乱码并误报读取成功。

### 2. 保留段落样式修订 .docx 与按坐标读写 .xlsx 公式

- **保留格式修改 `.docx` 正文与表格**：调用 `pc_edit_file` 修改 `.docx` 文件时，传入待替换的 `old_text` 与 `new_text`（多处替换可传 `edits` 数组或设 `replace_all=True`）。底层 XML 修订逻辑支持跨 `<w:r>` 文本片段匹配段落与表格文字，替换后保留首片段原有的字体、字号、加粗、斜体与颜色样式，自动补齐空白符保留属性：
  ```text
  @Cosmos 读取 D:\Work\my-project\docs\项目验收报告.docx，将文档中的“测试环境待部署”替换为“生产环境已完成上线验收”，保留原有的标题与表格字体样式。
  ```
- **按单元格坐标读写 `.xlsx` 数值与公式**：调用 `pc_edit_file` 修改 `.xlsx` 工作簿时，将 `old_text` 写为 `工作表名!单元格坐标`（如 `Sheet1!F12`），将 `new_text` 写为目标值或以 `=` 开头的 Excel 公式（也可通过 `edits` 列表一次性原子更新多格数据）：
  ```text
  @Cosmos 查看 D:\Work\my-project\finance\月度核算.xlsx 的表头结构，在 Sheet1!D14 填入求和公式 =SUM(D2:D13)，并在 Sheet1!E14 填入均值公式 =AVERAGE(E2:E13)。
  ```

### 3. Word / Excel 打开占用保护与 .undo_history 一键回滚

- **文件打开占用保护（`ERR_OFFICE_FILE_LOCKED`）**：当目标 `.docx` 或 `.xlsx` 正被本地 Microsoft Word、Excel 或 WPS 打开编辑（同目录存在 `~$` 锁文件或操作系统底层文件句柄被独占）时，`pc_edit_file` 会立即中止写入并返回结构化错误码 `ERR_OFFICE_FILE_LOCKED`，防止覆盖你正在桌面软件里编辑但尚未保存的内容（同目录下其他未锁文件的 `pc_read_file` 只读提取不受影响）。看到该提示时，在本地 Word / Excel 中按 `Ctrl+S` 保存并关闭该文档窗口，再让 AI 重试即可。
- **`.undo_history` 写前快照与无损撤回**：所有经由 `pc_edit_file`、`pc_write_file` 执行的代码修改与 `.docx` / `.xlsx` 二进制修订，都会在写入前自动向独立状态目录 `.undo_history` 保存完整快照（不会在你的项目目录或 Git 仓库里留下 `.bak` 脏文件）。若对修改结果不满意，可通过两种方式原样回滚：
  1. 在聊天框直接发送：`@Cosmos 把刚才对 D:\Work\my-project\finance\月度核算.xlsx 的修改撤回到上一版`（触发 `pc_manage_files(action="undo", path="...")`）；
  2. 打开本地 `Cosmos Studio` 控制台切到「实时任务与修改恢复」页，查看修改前后的 Diff 对比并点击撤回按钮。
- **可恢复回收箱替代物理直删**：需要清理旧文件或临时目录时，统一通过 `pc_manage_files(action="trash", path="...", reason="...")` 移入 `.undo_history` 回收箱，误删时随时可用 `pc_manage_files(action="restore", trash_id="latest")` 或在控制台恢复。

## 四、耗时编译与测试自动转 pc_bg_command 后台任务与状态轮询

### 1. 超 20 秒同步阈值自动转后台机制

`pc_run_command` 与 `pc_run_python` 均使用系统无窗口标志（`CREATE_NO_WINDOW`）在后台静默运行，不会弹出黑色终端框打断前台工作。为兼顾短命令即时返回与网页端连接器 `60` 至 `90` 秒的请求超时上限：

- 默认前台同步等待上限为 `20` 秒（`DEFAULT_SYNC_WAIT_CAP_SEC = 20.0`，单次可通过 `sync_wait_cap_sec` 在 `0.2` 至 `60` 秒范围内调整）。
- 若命令在 `20` 秒内执行完毕，直接返回退出码与标准输出；若超过 `20` 秒仍在运行（如全量 `pytest`、`npm run build`、`cargo test` 或数据处理脚本），执行器自动将其无缝升级为后台分离任务，立即返回 `job_id` 与日志文件绝对路径。

### 2. 主动后台启动、虚拟环境指定与轮询终止

对于已知耗时较长的构建、训练或全量回归测试，可直接指示 AI 按「后台启动 -> 分段轮询 -> 完成汇总」三步操作：

1. **指定环境启动后台任务**：调用 `pc_bg_command(action="start", command="pytest tests/ -v", cwd="D:\\Work\\my-project")` 立即拿到 `job_id`（耗时小于 `50ms`）；支持同时传入 `python_path`、`venv` 或 `conda_env` 参数指定本机虚拟环境或 Conda 环境（Windows 下自动将 `pythonw.exe` 映射为无窗口 `python.exe` 以确保标准输出完整写入日志）。
2. **长轮询进度与读取尾部日志**：调用 `pc_bg_command(action="wait", job_id="<job_id>", wait_seconds=20, tail_lines=80)`（或 `pc_get_status(job_id="<job_id>", wait_seconds=20)`）阻塞等待最多 `20` 秒，若任务在此期间结束则立即返回真实 `exit_code` 与最后 `80` 行输出；若仍在运行则继续下一轮轮询或读取日志文件。
3. **中途终止异常任务**：发现测试死循环或参数有误时，调用 `pc_bg_command(action="kill", job_id="<job_id>")` 清理整个子进程树，也可在本地控制台「实时任务与修改恢复」页点击「终止全部在途任务」。

## 五、按需热开启受管浏览器（browser）与桌面窗口自动化（cua）扩展包

### 1. 开启方法与连接器 Schema 刷新提示

默认配置下仅开放 `16` 项核心文件与终端工具。当需要让网页端 AI 验证本地启动的前端页面、抓取动态渲染网页，或操作本地 Windows 桌面 GUI 程序时，可按需热开启两个可选扩展包：

- **方式 A（控制台图形开关）**：打开本地 `Cosmos Studio` 控制台切到「工具中心与安全开关」页，确认当前处于 `L3` 工作区内顺畅开发（或 `L4` 全盘顺畅开发（不限目录）；`L1` 只读浏览与 `L2` 仅改文件禁跑命令模式下外设扩展包自动置灰禁用），打开 **「受管浏览器包」**（注册 `pc_browser_use`）与 **「桌面窗口操控包」**（注册 `pc_cua_window`，仅 Windows 系统可用，macOS / Linux 自动跳过）。
- **方式 B（命令行开关）**：
  ```bash
  # 同时开启受管浏览器包与桌面窗口操控包（cua 与 desktop 互为同义别名）
  cosmos-mcp permissions --enable-pack browser,cua

  # 用完后随时关闭扩展包恢复精简 16 项工具面
  cosmos-mcp permissions --disable-pack browser,cua
  ```
- **开启后的连接器刷新步骤**：网页版 Gemini 与网页版 ChatGPT 均在对话初始化时静态加载当时的工具 Schema 清单。热开启或关闭 `browser`、`cua` 扩展包后，若发现当前旧对话提示找不到 `pc_browser_use` 或 `pc_cua_window`，请按两步刷新：
  1. 在网页版连接器设置页点击刷新（网页版 ChatGPT 打开连接器详情点击 `Refresh`；网页版 Gemini 直接新建会话即可重新拉取，若仍未显示可在 `https://gemini.google.com/customize/connectors` 重新开关一次）；
  2. **新建一个聊天窗口**并在首句输入 `@你在连接器里填写的名称`（如 `@WebAI2PC` 或 `@Cosmos`）发起任务。

### 2. 零抢焦点后台运行边界

两个外设扩展包均严格遵守零抢占前台焦点与个人数据隔离原则，让你在自己电脑上打字、看文档的同时，AI 在后台独立完成操作：

1. **受管浏览器（`browser` -> `pc_browser_use`）运行边界**：
   - **独立配置目录隔离**：固定使用 `<状态目录>/browser_profile` 独立目录运行（安装了 `playwright` 时优先使用，未安装时自动复用本机 Chrome / Edge 无头 CDP 协议），完全不读取、不切换、不关闭你正在日常使用的个人浏览器窗口与标签页。
   - **真实可见元素过滤与下载归档**：执行 `snapshot`、`click`、`fill`、`select` 时自动校验元素及父级节点的可见属性与非零尺寸，屏蔽隐藏的移动端冗余 DOM（目标不可见时返回 `ERR_ELEMENT_HIDDEN`）；文件下载自动落入当前可读写工作区，同步 SSRF 守卫自动阻断 `file://` 协议、云元数据地址及本机管理端口。
   - **无焦点抢占人工登录窗**：遇到需人工扫码登录的页面时，调用 `open_login_window` 以系统 `SW_SHOWNOACTIVATE` 标志弹出受管窗口，不会夺走你当前正在输入的窗口焦点。
2. **桌面窗口自动化（`cua` -> `pc_cua_window`，仅 Windows）运行边界**：
   - **离屏抓图与后台消息投递**：全程采用 `PrintWindow(2)` 离屏抓图、UIAutomation 控件树解析与后台窗口消息合成（长边超过 `1440px` 的高分屏窗口自动记录缩放比例 `scale_factor`，后续点击与滚动在默认 `coord_space="auto"` 下自动反算回真实客户区像素坐标）；每次调用前后核验前台激活窗口句柄不变、物理鼠标光标不移动、系统剪贴板不被覆盖。
   - **工作区归属围栏与未保存保护**：在默认 `L3` 安全模式下，仅允许枚举和操控归属当前开放工作目录或由当前会话进程启动的窗口，禁止触碰无关个人聊天软件或系统设置窗；遇到系统锁屏或黑屏返回 `ERR_SCREEN_LOCKED_OR_BLACK_FRAME`；尝试关闭标题带未保存星号标记的窗口时自动拦截，需保存文件时通过 `send_keys(value="ctrl+s")` 向目标句柄后台发送快捷键。
